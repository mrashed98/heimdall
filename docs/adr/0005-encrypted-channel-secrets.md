# Console channel secrets encrypted in Postgres

Admins can add alert channels in the web console, and those channels need secrets (webhook URLs, tokens, passwords) that work as soon as the channel is saved. They are stored in Postgres, the only state Heimdall has, encrypted with AES-256-GCM (`ring`, already in the tree) under `HEIMDALL_SECRET_KEY`, with a random nonce per write and the channel name as associated data so a ciphertext cannot be moved to another row. Secrets are write-only: no response, log or audit entry ever contains one. Two options were rejected. Having the console reference environment variable names only keeps secrets out of the database, but every new channel would still need a Secret change and a restart, which defeats the point of managing channels in the console. Having Heimdall write Kubernetes Secrets needs RBAC to write Secrets, ties Heimdall to Kubernetes, and goes against the spirit of ADR 0003 (Sight never reads Kubernetes Secrets). The cost is one more key to back up: if it is lost or changed, the stored secrets cannot be decrypted and must be re-entered, and there is no key rotation yet. A missing or malformed key turns console management off rather than stopping Heimdall, and config channels are unaffected.
